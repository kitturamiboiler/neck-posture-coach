# 자세 측정 실험 노트

시간순 실험 기록이다. 최신 귀 선택 수정은 문서 마지막의 **귀 좌우 대응 오류 재현 및 수정**을 따른다. 과거의 동일 이름 대응과 EMA는 현재 구현이 아니다.

## 현재 방향

이 프로젝트는 실시간 운동 코칭보다 첫 측정, 운동 수행, 재측정, 변화 확인 흐름에 맞춘다.

현재는 새 목 검출 모델을 만들지 않고, ML Kit가 이미 제공하는 기준점을 먼저 사용한다.

## 현재 검출 결과

- Face Detection은 귀 위치를 비교적 잘 잡는다.
- Pose Detection은 어깨 위치를 잡는다.
- Face Detection의 귀 좌표와 Pose Detection의 귀 좌표는 서로 다를 수 있다. 두 모델이 같은 이름의 랜드마크를 쓰더라도 실제로 추정하는 기준점이 같다고 보장할 수 없다.
- Face Detection의 얼굴 박스는 귀나 목 후보 영역을 완전히 포함하지 않을 수 있다. 박스는 측정 영역이 아니라 ML Kit가 판단한 얼굴 영역이다.
- 전면 카메라에서는 화면 기준 좌우와 ML Kit의 사람 기준 좌우가 다르게 보일 수 있다.

## 2026-09-14 실험 결과

| 항목 | 결과 | 판단 |
| --- | --- | --- |
| Face Detection 귀 | 실제 귀구멍 근처를 비교적 잘 잡음 | 측정 기준점으로 사용 |
| Pose Detection 귀 | 볼/광대 쪽으로 앞에 찍히는 경우가 있음 | 측정에서는 제외 |
| Pose Detection 어깨 | 어깨 기준점을 잘 잡음 | 측정 기준점으로 사용 |
| Face Mesh | 얼굴 기준점 보강은 가능하지만 목/어깨는 직접 제공하지 않음 | 지금은 보류 |
| 커스텀 Neck Detection | 데이터셋/학습/검증 부담이 큼 | 지금은 하지 않음 |

결론:

```text
Face Detection 귀 + Pose Detection 어깨 = 자세 측정 기준
```

현재 Pose Detection만으로 계산된 예시:

```text
Pose ear + Pose shoulder = neck 48 deg
```

이 값은 Pose 귀가 실제 귀구멍보다 앞쪽으로 찍힌 상태라 최종 측정값으로 쓰지 않는다.

## 임시 디버그 표시

- Face Detection 화면
  - 귀와 코 기준점을 흰 점으로 표시한다.
  - 얼굴 박스보다 넓은 흰 후보 박스를 표시한다.
  - 귀 기준점에서 아래로 기준선을 표시한다.

- Pose Detection 화면
  - 귀와 어깨 기준점을 흰 점으로 표시한다.
  - 같은 쪽 귀와 어깨를 흰 선으로 연결한다.
  - 귀-어깨 선의 각도를 표시한다.

## 각도 계산

귀와 어깨 좌표를 사용한다.

```text
dx = abs(earX - shoulderX)
dy = shoulderY - earY
angle = atan2(dy, dx)
```

`angle`은 어깨에서 귀로 향하는 선과 수평선 사이의 각도다. 90도에 가까울수록 귀가 어깨 위에 가깝다.

현재 측정 프로토타입은 ML Kit 입력 이미지 좌표에서 계산하고 도 단위로 표시한다. 화면 표시에는 `GraphicOverlay`의 확대·이동·반전 변환을 적용한다.

```java
double angle =
    Math.toDegrees(Math.atan2(shoulderY - earY, Math.abs(earX - shoulderX)));
```

현재 `PoseGraphic`의 각도 표시는 수직선 기준 편차를 확인하는 임시 디버그 값이다. 최종 측정 로직에는 그대로 사용하지 않는다.

## 2026-09-21 실기기 재확인

- 최초 실행 입력 크기가 `288x352`로 표시됐고, Face Detection 결과가 없어 선과 각도가 그려지지 않았다.
- 기본 크기 선택이 목표값 `480x360`보다 작은 `352x288`을 고르는 문제를 확인했다.
- 지원 크기 중 목표값 이상을 우선하도록 수정했다. 확인한 기기 지원 목록상 예상 선택값은 `640x480`이며, 수정 후 실제 입력 크기는 다시 확인해야 한다.
- 측정용 Face Detection은 윤곽선 검출을 끄고 `ACCURATE + LANDMARK_MODE_ALL`로 변경했다.
- 귀와 어깨가 모두 유효할 때만 그리던 방식을 바꿔, 검출된 귀 후보와 어깨 후보를 독립적으로 표시하도록 수정했다. 이후 안정화 버전에서는 유효한 측정에 안정화된 점을, 실패 상태에 원시 후보점을 표시한다.
- 수정 APK 빌드와 태블릿 설치는 성공했다.

### 내일 먼저 할 것

1. 태블릿 USB 디버깅 연결 후 `Java → LivePreviewActivity → Neck Posture Measurement`를 연다. 실제 입력 해상도와 전면 카메라 상태를 확인한다.
2. 기존 Face/Pose 화면과 통합 화면을 같은 촬영 조건에서 비교한다. 귀 위치, 같은 쪽 어깨 연결, 회전·좌우 반전 좌표가 맞는지 먼저 확인한다.
3. 몸을 고정했을 때 원시 좌표와 안정화 좌표를 함께 비교할 수 있도록 로그를 보완한다. 검출 누락, 측정 쪽 변경, 실제 이동을 구분한 뒤 필터 계수를 조정한다.
4. 현재 EMA는 검출 실패 시 이전 상태를 초기화하지 않는다. 재검출·인물 변경·카메라 전환 후 오래된 좌표가 섞이는 경우를 확인하고 초기화 조건을 보완한다. 실패 상태에서 원시 후보점으로 바뀌며 생기는 시각적 튐도 확인한다.
5. 양쪽 귀 검출만으로 정면을 판단하는 임시 규칙, 어깨 화면 이탈, 여러 사람 검출, 처리 실패 후 프레임 재개를 점검한다. 머리만 카메라로 돌리면 측정 조건도 달라지므로 검출 성공과 측정 적합성을 구분한다.
6. 계측 테스트 대기 원인을 확인하고 계산·안정화 동작을 검증한다. 좌표 대응과 반복성이 확인되면 촬영 품질 검사 → 3회 측정 중앙값 → 결과 → 로컬 기록 → 운동 안내 순서로 진행한다.

## 2026-09-25 수평 기준 각도 검증 표시

`Java → LivePreviewActivity → Neck Posture Measurement`에 적용했다.

| 표시 | 의미 |
| --- | --- |
| 청록색 수평선 | 선택한 어깨를 지나는 이미지 X축 방향 기준선 |
| 노란색 수직선 | 같은 어깨를 지나는 이미지 Y축 방향 기준선 |
| 흰색 연결선과 점 | 같은 쪽 Face 귀와 Pose 어깨의 EMA 좌표 |
| 어깨 중심 각도 호 | 귀 쪽 수평 반직선과 귀-어깨 연결선 사이의 각도. 전면 카메라 반전에도 같은 끼인 각도를 표시 |
| 하단 각도·비교 | 50도 미만 또는 이상. 미만이면 호가 주황색이며, 양쪽 모두 자가 참고용 표시 |
| 측정 대기 | 검출·품질 조건 미충족. 후보만 표시하고 각도와 비교 결과는 표시하지 않음 |

- 공식은 `degrees(atan2(shoulderY - earY, abs(earX - shoulderX)))` 그대로다. 선 길이는 이미지 좌표의 거리이며 cm가 아니다.
- 사용자 요청 기준 `50.0`은 `NeckPostureAngle.REFERENCE_ANGLE_DEGREES` 한곳에 둔다. 비교는 반올림 전 값에 적용하며, 정확히 50도는 미만이 아니다. 화면 숫자는 소수 둘째 자리로 반올림한다.
- 이 값은 C7을 기준으로 측정한 CVA가 아닌 **귀-어깨각**이다. 50도 미만을 거북목 진단, 50도 이상을 정상 판정으로 사용하지 않는다. 임상 기준과의 일치도는 검증되지 않았다.
- 귀 개수만으로 정면을 거부하던 조건을 얼굴 Euler Y로 교체했다. `abs(yaw) >= 36`을 임시 조건으로 사용하고 음수는 왼쪽, 양수는 오른쪽의 귀·어깨를 선택한다. 선택한 귀가 없으면 반대 귀로 대체하지 않는다.
- [ML Kit 얼굴 방향·랜드마크 문서](https://developers.google.com/ml-kit/vision/face-detection/face-detection-concepts)를 참고했다. 36도는 검출 실험용 설정이지 몸의 완전한 측면 촬영을 보장하는 기준이 아니다. 몸 방향·기기 기울기 검사는 아직 없다.
- 어깨 신뢰도 0.70, 프레임 내부 좌표, 귀가 어깨 위에 있는지 등의 검사는 유지한다. 여러 얼굴이 검출되면 측정을 중단한다. 높은 신뢰도가 실제 어깨 위치의 정확도를 뜻하지는 않는다.
- Logcat `NeckPostureProcessor`에서 얼굴 yaw, 귀 존재 여부, 원시 어깨, 원시 각도, EMA 좌표·각도와 기준 비교를 확인한다. 검출 누락 후 EMA는 초기화한다.

태블릿 연결 후 APK를 설치하고 같은 쪽 귀·어깨에 점이 찍히는지, 수평선부터 연결선까지 호가 맞는지 확인한다. 기기를 고정한 상태에서 자세를 바꿔 각도가 변하는지 확인하되, 촬영 거리·방향을 바꾼 값을 개선 결과로 비교하지 않는다. 3회 중앙값과 최종 결과 저장은 아직 구현하지 않았다.

## 2026-09-25 귀 표시가 볼·코 쪽으로 밀리는 문제

사용자 사진에서 측면의 귀 점이 볼 쪽에, 다른 자세에서는 코 근처에 표시됐다. 해당 각도는 신뢰할 수 있는 측정 결과로 기록하지 않는다. 사진만으로 모델 오검출과 표시 지연 중 어느 쪽인지 단정할 수 없다.

코드에서 확인한 문제와 수정:

- `CameraSource`가 `processByteBuffer` 반환 직후 배열을 카메라에 돌려주지만, 검출기는 비동기로 계속 읽을 수 있었다. 이제 공통 전달부에서 프레임 배열을 복사한다. Face/Pose와 배경 이미지가 재사용되는 카메라 배열을 참조하지 않는다. Java/Kotlin Camera1 경로에 공통 적용되며 CameraX는 변경하지 않았다.
- 귀·어깨 좌표 EMA를 제거했다. 기존 `alpha=0.20`은 일정한 속도로 이동할 때 약 4프레임의 지연이 생기므로 현재 영상의 귀와 이전 좌표를 섞은 점이 맞지 않을 수 있었다. **현재 점과 각도는 같은 프레임의 원시 좌표**이며 위의 EMA 관련 기록은 이전 구현이다. 원시 검출 노이즈는 다시 보일 수 있다.
- 흰 점 `L/R 귀 원시`는 Face의 EAR 결과다. 자홍색 십자 `코 원시`는 별도의 NOSE_BASE 결과다. 코 좌표를 귀 대신 연결하는 코드는 없다.
- Logcat에 LEFT_EAR / RIGHT_EAR / NOSE_BASE 원시 좌표를 각각 추가했다. 이전 프레임 혼합을 없앤 후에도 귀 점이 잘못된 위치에 고정되면 모델 자체의 검출 한계나 별도의 좌표 대응 문제를 추가 검증해야 한다.
- 귀 점을 임의로 옆으로 옮기거나 코를 귀로 대신 사용하는 보정은 하지 않았다. 이번 수정만으로 귓구멍 검출 정확도가 검증된 것은 아니다.

프레임 복사마다 할당이 추가된다. 성능 측정에서 문제가 확인되면 검출 완료 시점까지 버퍼를 소유하는 재사용 방식으로 개선한다.

검증: Debug 앱·테스트 APK 빌드 및 SM-T735N 설치 성공. `CameraFrameOwnershipTest`와 `NeckPostureAngleTest`를 실기기에서 실행해 **6개 테스트 통과**를 확인했다. 버퍼가 재사용돼도 처리 중·대기 프레임이 바뀌지 않는지, 각도 경계와 반전된 Canvas 축·연결선·호 픽셀을 검사했다. 이 자동 테스트는 사람의 귀 위치 검출 정확도를 검증하지 않는다. 수정 후 실제 측면 귀 위치는 사용자 재확인 대기다.

## 2026-09-25 귀 좌우 대응 오류 재현 및 수정

버퍼·EMA 수정 뒤에도 잘못된 귀가 선택된다는 보고를 받았다. 사용자가 제공한 전체 스크린샷을 태블릿에서 Face Detection으로 재검출했다. 사진은 저장소에 넣거나 외부로 업로드하지 않았다.

| 2560x1600 입력 | 얼굴 yaw | Face LEFT_EAR | Face RIGHT_EAR | 기존 선택 | 수정 선택 |
| --- | --- | --- | --- | --- | --- |
| 원본 스크린샷 | +83.20도 | (704.69, 575.07) | (790.26, 576.35) | RIGHT_EAR: 귀 앞쪽 | LEFT_EAR: 보이는 귀 영역 |
| 스크린샷 좌우 반전 | -82.27도 | (1781.01, 585.75) | (1863.73, 580.92) | LEFT_EAR: 귀 앞쪽 | RIGHT_EAR: 보이는 귀 영역 |

반전 사진의 수정 좌표를 원본 방향으로 되돌리면 약 (696.27, 580.92)다. 두 방향 모두 실제 보이는 귀 영역에 들어왔다. 기존 선택은 두 방향 모두 영역 바깥이었다.

원인은 `sideForYaw`로 정한 Pose 쪽에 **동일 이름의 Face EAR를 바로 연결한 것**이다. 현재 번들 Face 16.1.7의 재현 결과를 기준으로 `faceEarTypeForPoseSide` 한곳에서 대응한다:

- Pose LEFT_SHOULDER에는 Face RIGHT_EAR.
- Pose RIGHT_SHOULDER에는 Face LEFT_EAR.
- 정면 또는 선택한 귀가 없으면 각도를 내지 않는다. 화면 반전 때문에 이 대응을 다시 뒤집지 않는다.

이 결과는 현재 SDK와 이 재현 사진의 동작 근거이며 모든 모델 버전에 대한 일반적인 LEFT/RIGHT 정의를 주장하지 않는다. SDK 변경 시 같은 회귀 테스트를 재실행해야 한다. 기존 Face 단독 화면에서도 LEFT_EAR를 `R ear`로 표시하고 있었는데 통합 측정 경로가 이를 반영하지 못했다.

`EarReplayTest`는 선택한 점이 수동으로 지정한 귀 영역에 있는지, 이전 선택이 영역 밖인지 원본·반전 입력 모두 검사한다. 로컬 테스트용 `ear-regression.png`가 없으면 해당 사진 테스트는 건너뛰며 통과 증거로 집계하지 않는다. 사진 파일은 테스트 후 태블릿에서 제거한다.

[FaceLandmark API](https://developers.google.com/android/reference/com/google/mlkit/vision/face/FaceLandmark)는 EAR를 귀 위끝과 귓불의 중간점으로 설명한다. **귓구멍 자체를 정밀 검출하는 모델은 아니다.** 이번 수정은 잘못된 귀 후보 선택을 고치는 것이며 귓구멍·C7 위치나 임상 측정 정확도를 검증한 것은 아니다.

최종 검증: 수정 앱·테스트 APK 빌드 및 SM-T735N 설치 성공. 실기기에서 **8개 테스트 모두 통과**했으며, `EarReplayTest`도 실제 사진을 사용해 실행됐다(건너뛰기 아님). 사진 임시 사본은 테스트 후 제거했다. 현재 라이브 카메라에서 다른 자세·조명에 대한 정확도 확인은 별도로 남아 있다.
