## 목적과 제품 범위

조원이 전달한 공통 스타일 보드와 대표 화면 3장을 바탕으로 Android 화면을 구성합니다. 목표 설정, 오늘, 운동 안내·타이머·실천 확인, 사진 준비·촬영·귀/C7 확인·결과·저장, 기록, 설정을 연결합니다.

실제 카메라 분석과 DB 저장은 Android 앱에서 수행합니다. Figma는 화면 전환·선택·확인·재시도 흐름을 점검하는 프로토타입입니다. 정상·위험 등급, 각도별 운동 처방, 자동 C7 검출은 추가하지 않습니다.

## 프레임 사용 규칙

1. 하나의 앱 화면은 최상위 프레임 하나로 만듭니다. 기준 크기는 360×800이며 상태바·앱바·본문·하단 내비게이션·시스템 영역을 구분합니다.
2. 반복 UI는 먼저 메인 컴포넌트로 만든 뒤 화면에 인스턴스를 배치합니다. 화면마다 버튼·텍스트·아이콘을 새로 그리지 않습니다.
3. 관련 요소의 세로·가로 정렬에는 Auto Layout을 사용합니다. 간격, 패딩, 너비·높이 정책을 지정합니다.
4. 하위 프레임은 스크롤 뷰포트, 가로 선택지, 같은 정보의 묶음, 실제 개별 카드 등 구조적 이유가 있을 때만 만듭니다.
5. 텍스트 하나나 아이콘 하나를 감싸는 빈 프레임, 내용 없는 프레임, 동일 크기의 중복 래퍼를 만들지 않습니다. 48px 터치 영역 확보처럼 목적이 있는 래퍼는 허용합니다.
6. 구성 요소를 무조건 그룹·프레임으로 중첩하지 않습니다. 새 프레임이 어떤 정렬·스크롤·터치 문제를 해결하는지 이름으로 설명할 수 있어야 합니다.
7. 화면 내용은 Auto Layout으로 배치합니다. 캔버스에서 화면을 나열하는 위치와 사진 위 기준점 같은 겹침 요소만 절대 좌표를 허용합니다.
8. 컴포넌트 인스턴스를 분리하지 않습니다. 재사용 요소의 변경은 메인 컴포넌트나 속성·Variant에서 처리합니다.
9. 화면 상태를 새로 만들 때 기존 상태와의 실제 기능 차이를 확인합니다. 색상이나 숫자만 확인하려고 무분별하게 복제하지 않습니다.

색상은 Primitive 값과 Semantic 별칭으로 연결합니다. 메인 컴포넌트의 채움·선·글자·주요 간격·모서리를 변수에 바인딩합니다. 원안 글꼴은 Pretendard입니다. 현재 Figma 실행 환경에서 사용할 수 없어 Noto Sans KR로 임시 작성했으며, 최종 타이포 완료로 간주하지 않습니다. Pretendard 사용 가능 환경에서 공통 텍스트 스타일을 교체하고 다시 확인해야 합니다.

## 컴포넌트와 상태

| 컴포넌트 | 역할 / 속성 |
| --- | --- |
| Button | Primary·Secondary × Default·Disabled·Loading, Label·Icon·Show icon |
| IconButton | 48×48 아이콘 터치 영역, Icon 교체 |
| Choice | Selected·Default, Label |
| Check | Unchecked·Checked, 확인 문구 |
| Header | Root·Back, 제목 |
| Notice | Info·Warning·Error, 문구 |
| Measurement | 사진별 이름과 값 |
| Timer | 시간과 보조 문구 |
| Navigation | Today·History·Settings |
| Android/StatusBar, SystemNavigation | 공통 시스템 영역 |
| Icon/* | 버튼과 내비게이션에서 재사용하는 기호 |

아이콘별로 버튼 Variant를 만들지 않고 INSTANCE_SWAP을 사용합니다. 글자는 TEXT 속성으로 변경하고, 화면에서는 그 속성을 덮어씁니다. 스크롤 콘텐츠와 바닥 내비게이션을 중복 래퍼로 감싸지 않습니다.

## 프로토타입 시작점

| 시작점 | 확인할 흐름 |
| --- | --- |
| 01 목표부터 시작 | 기본 4주/3분 예시, 목표 조합 선택과 오늘 화면 |
| 02 오늘의 운동 | 상태 확인, 시작, 일시정지·재개, 실제 수행 확인, 완료 기록 화면 |
| 03 사진 점검 | 기본 왼쪽/전면 예시, 조건 확인·권한·3장 확인·결과·저장·기록 |
| 04 품질 보류 | 기준점 재확인·재촬영, 결과 저장 보류 |
| 05 권한 확인 | 허용·거부·재시도 |
| 06 저장 실패 | 재시도·결과 복귀 |

촬영 대기와 운동 종료는 짧은 시간 경과로 전환하는 시연입니다. 실제 3분/5분 타이머와 촬영 센서는 동작하지 않습니다. 값 52.5°·55.4°·55.7°는 기존 실촬영 기록의 예시이며 새 분석 결과가 아닙니다.

현재 Starter 플랜은 SET_VARIABLE 및 한 반응의 복수 Action을 허용하지 않습니다. 별도 화면 상태로 연결했으며 목표·촬영 옵션을 실제 앱처럼 전 경로에 저장·동기화하지 않습니다. 특히 완료·기록·결과 예시는 기본 4주/3분·왼쪽/전면 조건으로 검토합니다. 다른 옵션으로 들어가는 오늘 화면은 목표별로 구성했지만 지속적인 전역 상태 검증을 대신하지 않습니다.

## 사람의 확인과 다음 작업

- [ ] Pretendard 글꼴 교체 및 줄바꿈·높이 재확인.
- [ ] 조원 운동 이미지·영상 확인 후 실제 콘텐츠 적용. 현재 운동 이미지 영역은 준비 상태입니다.
- [ ] 사진 예시와 귀·C7 오버레이, 기준점 선택·이동 버튼의 최종 조작 디자인. 현재 사진 영역은 구조와 단계 확인용입니다.
- [ ] Android 시스템 바, 큰 글꼴·작은 화면, 스크롤·터치 접근성 검토.
- [ ] Figma Present에서 실제 클릭하며 전체 흐름 점검. 이번 검증은 연결 그래프·속성·대표 스크린샷 확인입니다.
- [ ] 마지막 48px 뒤로가기·초기 목표 헤더·처리 중 버튼 수정 후 시각 재확인. 최종 재캡처 요청은 Starter MCP 호출 한도 때문에 수행하지 못했습니다. 앞선 대표 화면과 컴포넌트 견본에서는 텍스트·카드 잘림을 확인하고 수정했습니다.
- [ ] 목표와 촬영 조건의 실제 상태 보존은 Android 앱과 맞춰 구현·검증.
- [ ] UI 검토 후 실제 앱 반영. 지금 Figma 화면은 앱에 적용된 상태가 아닙니다.
